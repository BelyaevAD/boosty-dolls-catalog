# Применяемые стандарты

## Архитектура

- Node.js 20+, ECMAScript modules, генерация статического dist.
- Минимум зависимостей; предпочтительно только стандартная библиотека Node.js.
- Публичная JSON-схема версионируется и валидируется.
- Канонический идентификатор профиля — lowercase Boosty slug, а не имя автора.

## Качество данных

- Узкие запросы по одной технике, бренду или формату.
- Состояния кандидата: pending, published, unqualified, fetch-error, removed, excluded.
- 404/410 считаются терминальными; 429/5xx/timeout — временными.
- Перед релизом errors пуст, totalOutstandingFetchErrors равен нулю.
- Не менее 20 новых профилей проверяются выборочно.

## Безопасность и приватность

- Никаких секретов, токенов, cookie, сертификатов или приватных ключей в коде и логах.
- Slug проверяется по allowlist; сетевые хосты фиксированы.
- В браузере используются textContent и безопасные атрибуты, не innerHTML для внешних данных.
- Внешние ссылки имеют rel=noopener noreferrer.
- CSP запрещает сторонний код, framing и небезопасные объекты.
- Публичные описания очищаются от e-mail, телефонов, платёжных реквизитов, мессенджеров, URL и призывов связаться.
- GitHub Actions использует минимальные permissions и закреплённые версии actions.

## Доступность

- Управление клавиатурой, видимый focus, корректные label и aria-live.
- Цвет не является единственным различителем моделей оплаты.
- Адаптивность от 320 px, учёт prefers-reduced-motion и контраст WCAG AA.
