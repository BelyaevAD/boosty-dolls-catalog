# Boosty Dolls Каталог

Открытый каталог русскоязычных и двуязычных кукольных авторов на Boosty. Проект помогает отдельно сравнивать два распространённых формата монетизации:

- **подписка** — регулярный доступ к закрытым публикациям и сообществу;
- **разовая покупка** — отдельный PDF, выкройка, урок, курс или другой платный материал.

Каталог не связан с Boosty, не продаёт места и не получает комиссию.

## Возможности

- карточный и табличный режимы;
- быстрый выбор «Подписка» или «Разовая покупка»;
- отдельный фильтр авторов, использующих оба формата;
- независимые ценовые ограничения и сортировки для подписки и разовых материалов;
- семь верхнеуровневых направлений и многозначные теги;
- поиск, активность, аудитория и рост между снимками;
- отдельная индексируемая страница каждого автора;
- sitemap.xml, RSS, robots.txt, JSON-LD и социальные метаданные;
- адаптивный интерфейс без стороннего JavaScript и трекеров;
- воспроизводимое автоматическое обновление публичных данных Boosty.

## Тематическая структура

1. Создание кукол.
2. Кастом и OOAK.
3. Одежда и выкройки.
4. Аксессуары.
5. Миниатюра и кукольные дома.
6. Коллекционирование и медиа.
7. История, ремонт и реставрация.

Вязаные, текстильные, BJD, арт-куклы, реборн, Blythe, Barbie, Monster High и масштабы 1:6/1:12 дополнительно представлены как фокус и поисковые признаки.

## Локальный запуск

Требуется Node.js 20 или новее.

```powershell
npm ci
npm run check
npx serve dist
```

Сайт будет собран в `dist/`. Для корректных canonical URL при сборке задайте:

```powershell
$env:SITE_URL = "https://example.github.io/boosty-dolls-catalog/"
$env:REPOSITORY_URL = "https://github.com/example/boosty-dolls-catalog"
npm run build
```

## Обновление данных

Обычный еженедельный запуск:

```powershell
npm run update:data
npm run check
```

Полный проход без общего лимита кандидатов:

```powershell
$env:DISCOVERY_MAX_CHECKS = "all"
$env:BOOSTY_SEARCH_MAX_QUERIES = "49"
npm run update:data
npm run check
```

Все запросы к Boosty проходят через общий планировщик и cooldown. Переменная `BOOSTY_REQUEST_INTERVAL_MS` регулирует минимальный интервал. HTTP 404/410 считаются терминальными, а 429/5xx/timeout остаются временными ошибками.

Перед выпуском обязательно проверяются:

- `data/latest-update.json`: `errors` пуст, `totalOutstandingFetchErrors` равен нулю;
- уникальность slug и Boosty URL;
- типы и диапазоны цен;
- соответствие модели оплаты фактическим уровням или платным постам;
- отсутствие контактных данных в публичных текстах;
- минимум 20 новых авторов и все необычно широкие классификации;
- `npm run check` и `git diff --check`.

## Данные

- `data/channels.json` — очищенный публичный каталог.
- `data/raw/boosty-candidates.json` — техническая очередь кандидатов и состояния проверки.
- `data/manual-exclusions.json` — осознанные ручные исключения.
- `data/latest-update.json` — отчёт последнего прохода.
- `data/history/` — компактные снимки для расчёта динамики.

Публичная схема версии 2 хранит цены раздельно:

- `minSubscriptionPriceRub`, `maxSubscriptionPriceRub`, `tiers`;
- `minOneOffPriceRub`, `maxOneOffPriceRub`, `oneOffItems`;
- `paymentTypes`: `subscription`, `one-off` или оба значения.

Разовый материал определяется среди последних 20 публично доступных метаданных публикаций. Это не гарантирует, что он новый или продолжает продаваться — условия нужно перепроверять на Boosty.

## Правила включения

Публикуется профиль, который:

- русскоязычный или двуязычный;
- имеет публикации и не заблокирован;
- не помечен как adult;
- явно относится к куклам либо содержит не менее двух подтверждённых кукольных материалов;
- имеет хотя бы один платный уровень подписки или разовый платный материал.

Смешанные рукодельные профили проходят только при подтверждённой кукольной специализации. Публичное число подписчиков показывается как размер аудитории и не трактуется как число платящих людей.

## Безопасность и приватность

- нет cookies, аналитики и стороннего JS;
- аватары и платные изображения не копируются;
- внешние ссылки открываются только по действию пользователя;
- CSP запрещает сторонний код и встраивание сайта;
- slug и сетевые хосты проверяются по allowlist;
- e-mail, телефоны, платёжные реквизиты, мессенджеры, URL и прямые инструкции связаться удаляются из публичных описаний;
- токены, cookies, browser storage и авторизационные заголовки не используются и не сохраняются.

## Автоматизация и публикация

Workflow `.github/workflows/update-data.yml` обновляет каталог по расписанию, создаёт изменения и запускает проверки. Workflow `.github/workflows/pages.yml` собирает статический сайт и публикует `dist/` в GitHub Pages с минимальными permissions.
