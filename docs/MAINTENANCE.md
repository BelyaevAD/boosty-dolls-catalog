# Сопровождение Boosty Dolls Каталога

Документ предназначен для разработчиков и сопровождающих. Пользовательское описание находится в [README](../README.md).

## Структура данных

- `data/channels.json` — очищенный публичный каталог схемы 2;
- `data/raw/boosty-candidates.json` — очередь кандидатов и состояния проверки;
- `data/manual-exclusions.json` — проверенные вручную ложные совпадения;
- `data/history/` — датированные снимки аудитории и цен;
- `data/latest-update.json` — отчёт обновления и состояние очереди.

Основная категория хранится в `category`, многозначные разделы — в `topics`. Формат оплаты хранится в `paymentTypes`. Поля подписки имеют префикс `Subscription`, разовых материалов — `OneOff`; объединять их в общую «минимальную цену» запрещено.

На публичный сайт не попадают поисковые доказательства, необработанные описания, внешние ссылки автора, контакты и служебные оценки релевантности.

## Автоматические процессы

- **CI** проверяет данные, тесты и статическую сборку.
- **Weekly data refresh** по пятницам обновляет профили и очередь кандидатов, затем фиксирует только проверенные изменения в `data/`.
- **Deploy GitHub Pages** собирает и публикует `dist/`.

GitHub Actions закреплены полными commit SHA, workflows используют минимальные permissions, npm устанавливается через lockfile с отключёнными lifecycle scripts.

## Источники и запросы

Порядок discovery:

1. публичные рубрики Boosty `art` и `lifestyle_and_hobbies` с кукольными признаками в заголовке;
2. 49 узких запросов по публичному поиску постов Boosty;
3. актуальный русский индекс Common Crawl;
4. внешняя поисковая выдача и GitHub-упоминания как вторичные источники.

Каждый Boosty-запрос проходит через `fetchBoostyJson`. Нельзя добавлять прямой `fetch`, отдельный limiter или обход общего cooldown.

## Квалификация

Профиль публикуется, если:

- русскоязычный или двуязычный;
- имеет публикации, не заблокирован и не adult;
- содержит явный кукольный профильный признак либо не менее двух релевантных кукольных материалов;
- имеет платный уровень подписки или отдельный платный пост.

Смешанные рукодельные профили допускаются только при подтверждённой кукольной части. 404/410 — терминальное отсутствие; 429/5xx/timeout — временная ошибка.

## Ручной и полный запуск

```powershell
npm run update:data
npm run check
```

Для полного прохода:

```powershell
$env:DISCOVERY_MAX_CHECKS = "all"
$env:BOOSTY_SEARCH_MAX_QUERIES = "49"
$env:BOOSTY_SEARCH_MAX_PAGES = "2"
$env:BOOSTY_SEARCH_PAGE_SIZE = "40"
npm run update:data
npm run check
```

Для детерминированного повторного запуска до 250 slug используйте `DISCOVERY_SEEDS_ONLY=1`, `DISCOVERY_SEED_SLUGS` и `SKIP_PUBLISHED_REFRESH=1`.

## Выпускной чек-лист

1. `data/latest-update.json.errors` пуст.
2. `totalOutstandingFetchErrors` равен нулю.
3. Проверены минимум 20 новых профилей и широкие классификации.
4. Нет дубликатов slug и URL.
5. Публичные тексты не содержат e-mail, телефонов, платёжных номеров, мессенджеров, URL и инструкций связаться.
6. `npm run check` проходит.
7. `git diff --check` проходит.
8. GitHub Actions зелёные.
9. GitHub Pages отвечает HTTP 200; проверены обе модели оплаты и мобильный вид.

## Приватность

Сайт не устанавливает cookies, не использует аналитику, сторонний JavaScript, iframe или удалённые изображения. Нельзя сохранять токены, cookies, browser storage, JWT, заголовки авторизации, закрытые материалы или сырые артефакты авторизованного браузера.
